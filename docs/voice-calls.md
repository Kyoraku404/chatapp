# Direct voice calls

RUSH supports live, one-to-one audio calls in direct conversations. The call button appears in the DM header. Incoming calls ring while the recipient has the app open, even if a different conversation is selected. Recipients can answer or decline; either person can mute or hang up.

Incoming calls play a repeating RUSH five-note ringtone. Callers hear a quieter ringback pattern while waiting. If the 90-second ringing window expires without an answer, the caller hears three short “tit tit tit” notes and sees a no-answer message. Answering, declining, or hanging up stops the ringtone. The sounds are synthesized locally; no audio file or recording is sent. Some browsers block sound until the user interacts with the page, so the call panel offers an **Enable ringtone** button when needed.

The browser asks for microphone access when starting or answering a call. Audio travels directly between browsers through WebRTC. The existing Firestore `users/{uid}/private/voiceCall` document carries the offer, answer, status, and ICE candidates. Only the document owner can read it under the existing rules. The session-verified `/api/dm/calls` route updates both participants' copies in transactions after checking DM membership and both block directions. Calls ring for up to 90 seconds; active call records expire after four hours. Hangup and normal navigation end calls sooner. RUSH does not record audio.

For reliable calls across restrictive networks, configure a TURN server that supports coturn's shared-secret REST credentials. Set `TURN_URLS` to comma-separated `turn:` or `turns:` URLs and `TURN_SECRET` to the same secret configured as coturn's `static-auth-secret` with `use-auth-secret`. The server issues one-hour credentials from `/api/dm/calls/ice`; the shared secret stays on the server. Without TURN configuration, calls use a public STUN server and can fail when the peers cannot reach each other directly. Microphone access requires HTTPS outside localhost.

On a phone, opening a local development server at `http://192.168.x.x` (or another LAN address) will never show a microphone prompt. `localhost` is an exception, but on a physical phone it refers to the phone itself, not the computer running RUSH. Use an HTTPS address on the phone, open RUSH directly in Safari or Chrome, and tap Call or Answer. If access was previously denied, allow the microphone for that site in the browser's site settings and check the phone's browser microphone permission. RUSH now shows specific guidance for insecure addresses, blocked permissions, and unavailable microphones, plus a **Check mic** action to retry the browser request after a failure.

No new Firestore rule deployment or database migration is required. The call inbox remains ephemeral product state in each user's private document and is overwritten by the next call.

If both phones show **Connected** but are silent, tap **Play call audio** on each phone and check that neither microphone is muted and media volume is up. If the call remains at **Connecting audio**, candidate exchange or network traversal has failed; configure TURN for calls across different networks. RUSH sends early ICE candidates even when they arrive before the call's Firestore subscription, so a slow signaling update no longer strands the audio connection.
